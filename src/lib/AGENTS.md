# src/lib rules
- Fast website prefill uses the linked Firecrawl gateway, public HTTPS DNS names only, and at most homepage plus same-origin contact page; suggestions fill blank fields and never establish ownership or consent. Why: reduce typing without trusting website content or making local arbitrary-URL requests.
- Cold Storage Coin sticker invoices use a static TXC address, TSD only, one active checkout per address, a pre-checkout transaction snapshot, exact full-sale matching (including verified Give splits), and atomic sticker txid claims before recording or settlement. Why: a shared address must not miscredit concurrent or historical payments.
- eGiving community splits: only Omni send-to-many TSD credits to stores with egiving_enabled qualify, and every non-merchant output must be an active egiving_recipients address (exactly one program, at least one church, shares summing to the invoice); the merchant slice must reach (100 - EGIVING_DISCOUNT_PCT)% with no tolerance, and the invoice is tagged payment_program/discount_usd before settling. Why: a split must never let ordinary underpayments through.
- The eGiving discount comes from EGIVING_DISCOUNT_PCT in src/lib/egiving.ts, never from stores.egiving_discount_pct; that column is read-only to authenticated (column-level UPDATE/INSERT revoked) and shown disabled in the merchant UI. Why: the eGiving wallet hard-codes its 8% church / 2% program split, so a per-store value would make its fixed payment arrive underpaid.
- The public eGiving cause list (/api/public/v1/egiving/causes) comes only from get_public_egiving_causes() (active churches, never the program) and every response is TXC-message-signed with a key derived from EGIVING_LIST_SIGNING_KEY. Why: wallets pin the signer address so a compromised server cannot swap a church address.
- eGiving churches and participating merchants are managed only in Admin → Give; the HME Give signed-list feed (src/lib/hme-give-registry*) is switched off via HME_GIVE_SYNC_ENABLED, so the cron and /api/public/hooks/hme-give change nothing. Why: Bobby chose NectarPay as the single place to manage Give.
- Fast Start merchant signatures are image files in the private fast-start-signatures bucket (fast_enrollments.signature_path); the browser never lists or reads that bucket, and src/lib/fast-consent.server.ts hands the image back only through an admin-checked server function. Why: the drawing is evidence of the merchant's agreement and must stay readable later without becoming publicly fetchable.
- Stores without an activated Cold Storage Coin get slug stickers at /s/<url_slug> (src/lib/store-sticker.server.ts): each scan opens a chain-less invoice so /i/<id> derives a fresh address from the store wallet; coin-backed stores resolve to their coin sticker. Why: static-address guards apply only to coin stickers.
